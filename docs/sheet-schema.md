# 行程資料表規格（Google 試算表 → 網頁）

> 狀態：**試算表已建立**（Google Drive「東京 2026 行程」），網頁還沒改成讀取試算表，目前的行程資料仍然寫在 `tokyo-2026/index.html` 裡。

## 目標

- **試算表負責記錄**：依「東西的種類」分表，例如航班、住宿、交通、美食、店家、景點、購物清單、花費、行前準備。我們兩個用手機的 Sheets app 就能新增和修改。
- **網頁負責顯示**：網頁從這些表**自動組出每天的行程**，畫出時間軸和地圖，並列出口袋名單、購物清單和準備清單。
- **同一份資料可以給其他工具用**：例如匯入 Google 我的地圖。

## 架構

```
Google 試算表「東京 2026 行程」
  ✈️ 航班 · 🏨 住宿 · 🚄 交通 · 🍜 美食 · 🛍️ 店家 · 🏯 景點
  🎁 購物清單 · 💴 花費 · 🎒 行前準備 · 每日 · 選項
        │  檔案 → 共用 → 發布到網路（整份文件，CSV）
        ▼
tokyo-2026/index.html
  讀取各表的 CSV → 檢查資料 → 組出每日時間軸、地圖、口袋名單、購物清單、準備清單、花費統計
```

- 讀取網址格式：`https://docs.google.com/spreadsheets/d/e/<發布ID>/pub?gid=<工作表ID>&single=true&output=csv`
- 網頁只能**讀**試算表，所有新增、修改都在試算表裡做。
- **離線備援**：每次讀取成功，網頁都會在這支手機上存一份資料。讀不到試算表時改用這份存檔，並在頁面上方顯示「目前顯示的是 MM/DD HH:MM 的資料」。
- **Google 發布的內容有快取**：改完之後，可能要等 1–5 分鐘網頁才會更新。

## 每天的行程怎麼組出來

網頁把下列資料依「天 + 時間」排在一起，就是當天的時間軸：

| 來源 | 什麼情況會出現在第 N 天 |
|---|---|
| 航班 | 日期等於第 N 天。依起飛或抵達時間排入 |
| 住宿 | 入住日等於第 N 天，就以 Check-in 時間顯示「入住」。退房日等於第 N 天，就以 Check-out 時間顯示「退房」 |
| 交通、美食、店家、景點 | 「天」欄位填 N |

- **「天」欄位空白的美食、店家、景點**，代表「想去但還沒排」，會自動出現在**口袋名單**。所以不用另外一張口袋名單表。
- 第 N 天的日期由「每日」表的日期決定。沒有「每日」表時，以 Day 1 = 2026/12/25 往後推算。
- **每晚住哪裡**：日期落在「入住日 ≤ 當天 < 退房日」的那一段住宿。日期重疊時，以入住日比較晚的那一段為準，例如 12/27 住輕井澤，淺草的房間保留。
- **地圖**：當天有經緯度的項目會依時間順序標上編號，第一個和最後一個自動標成起點和終點。

## 通用規則

- **第 1 列是表頭**，網頁是用**欄位名稱**找資料，所以欄位可以調換位置。表頭列有設保護（警告模式）。
- **可以自己加欄位**：網頁不認得的欄位會被忽略。試算表是公開的，見「隱私」。
- **整列空白會被忽略**。格式有問題的列會被跳過，並列在網頁最下方的「資料問題」區塊，寫出是哪張表的第幾列、什麼問題。
- **說明類欄位**支援 `**粗體**` 和儲存格內換行，不支援其他 HTML。
- **時間**：`HH:MM`（24 小時制）。時間欄已設成純文字，輸入 `15:30` 不會被轉成別的格式。
- **日期**：`YYYY/MM/DD`。
- **經緯度**：必須查證，不可以用猜的。要落在日本範圍內（緯度 24–46、經度 122–154）。空白時，地圖上不標，卡片顯示「待確認位置」。
- **Google 地圖按鈕**：使用「地圖搜尋」欄位產生 `https://www.google.com/maps/search/?api=1&query=<地圖搜尋>`。這欄空白時，改用「名稱」。
- **狀態**：已訂／已定／草稿／待確認。新增的內容預設是「草稿」。
- **重點**（核取方塊）：勾選的卡片用粗框顯示。
- **英文小標**：選填，用來覆蓋卡片右上角的英文標籤，例如 `Lunch`。空白時用類型的預設值。
- **提議者／新增日期**：用來標示是誰加的。新增日期晚於這支手機上次開網頁的時間，就標 NEW；第一次開啟時，改標 7 天內新增的項目。

## 每日（選填）

Day 1–8 的日期、副標、標題、簡介、住宿（選填）、狀態。沒有這張表時，網頁只顯示日期。

## 選項

所有下拉選單的來源。每一欄是一組選項：天、狀態、人、預約、美食類型、店家類型、景點類型、交通方式、花費分類、付款方式。

- **只能新增選項，不要改名或刪除已有的選項**，網頁的顏色對照是照名稱判斷的。新增的類型會用預設的灰色顯示。

## 留在網頁程式碼裡的內容

封面、行前提醒（含小兒急診等緊急資訊）、購物指南、交通說明卡片、預算。這些內容幾乎不會改，排版也比較複雜。

## 隱私

試算表發布到網路後，**知道網址的人都看得到**：

- 可以寫：航班號碼、飯店名稱、大概區域、店家的公開地址。
- **不可以寫**：訂位代號、確認碼、護照資料、保單號碼、電話、email、我們住宿的詳細門牌地址。
