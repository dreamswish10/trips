# 行程資料表規格（Google 試算表 → 網頁）

> 狀態：**試算表已建立**（Google Drive「東京 2026 行程」），網頁還沒改成讀取試算表，目前的行程資料仍然寫在 `tokyo-2026/index.html` 裡。

## 目標

- **試算表負責記錄**：行程、店家、準備清單都寫在一份 Google 試算表裡，我們兩個用手機的 Sheets app 就能新增和修改，不需要會寫程式，也不需要 AI 訂閱。
- **網頁負責顯示**：網頁讀試算表的資料，畫出時間軸、地圖、口袋名單。改了試算表，重新整理網頁就看得到。
- **同一份資料可以給其他工具用**：例如匯入 Google 我的地圖。

## 架構

```
Google 試算表（一趟旅行一份）
  ├─ 每日
  ├─ 行程
  ├─ 口袋名單
  ├─ 準備清單
  ├─ 飯店
  └─ 選項（下拉選單的來源）
        │  檔案 → 共用 → 發布到網路（每張工作表各發布一個 CSV 網址）
        ▼
tokyo-2026/index.html
  讀取 CSV → 檢查資料 → 畫出每日時間軸、地圖、口袋名單、準備清單
```

- 讀取網址格式：`https://docs.google.com/spreadsheets/d/e/<發布ID>/pub?gid=<工作表ID>&single=true&output=csv`
- 網頁只能**讀**試算表，所有新增、修改都在試算表裡做。
- **離線備援**：在日本行動網路不穩時也要能看行程。
  - 每次讀取成功，網頁都會在這支手機上存一份最後一次的資料。
  - 讀不到試算表時，網頁改用這份存檔，並在頁面上方顯示「目前顯示的是 11/15 21:30 的資料」。
- **Google 試算表發布到網路的內容會有幾分鐘快取**：改完之後，可能要等 1–5 分鐘網頁才會更新。

## 通用規則（適用所有工作表）

- **第 1 列是表頭**，網頁是用**欄位名稱**找資料，不是用欄位順序，所以欄位可以調換位置。表頭列會設成保護，避免被誤改。
- **可以自己加欄位**：網頁不認得的欄位會直接忽略，例如想加一欄「私下備註」。不過還是要記得試算表是公開的，見下方「隱私」。
- **整列空白會被忽略**。
- **格式有問題的列**會被跳過，例如缺少必填欄位、時間格式錯誤。網頁最下方會有一個「資料問題」區塊，列出是哪張工作表的第幾列、什麼問題，方便回去修正。
- **說明類欄位**支援兩種格式：`**粗體**`，以及在儲存格內換行（手機上長按換行，電腦上按 Alt+Enter）。不支援其他 HTML。
- **經緯度**：緯度和經度都要是數字，而且要落在日本的範圍內（緯度 24–46、經度 122–154）。不符合的話，就不會標在地圖上，並會列在「資料問題」裡。經緯度**必須查證**，不可以用猜的（見 `AGENTS.md`）。
- **Google 地圖按鈕**：使用「地圖搜尋」欄位產生 `https://www.google.com/maps/search/?api=1&query=<地圖搜尋>`。這欄空白時，改用「名稱」。

## 工作表 1：每日

一天一列。

| 欄位 | 必填 | 格式 | 範例 | 網頁用途 |
|---|---|---|---|---|
| 天 | ✓ | 整數，下拉選單 | `5` | 對應 Day 分頁 |
| 日期 | ✓ | `YYYY/MM/DD` | `2026/12/29` | 顯示「12.29」；星期（火曜日）和日文日期（師走廿九日）由網頁自動產生 |
| 副標 | | 文字 | `搬家日` | 顯示成「火曜日 · 搬家日」 |
| 標題 | ✓ | 文字 | `淺草收尾 · 搬家到原宿` | 當天大標題 |
| 簡介 | | 文字，支援粗體 | `今天要從**淺草的飯店**換到…` | 標題下方的介紹 |
| 住宿 | | 文字，只寫名稱或區域 | `原宿 第二段飯店` | 選填。空白時由「飯店」工作表依日期自動帶入 |
| 狀態 | ✓ | 下拉選單：已訂／已定／草稿 | `草稿` | 顯示狀態標籤 |

- 地圖中心**不用填**，網頁會依照當天有座標的景點自動縮放。

## 工作表 2：行程

每個時間軸卡片一列。

| 欄位 | 必填 | 格式 | 範例 | 網頁用途 |
|---|---|---|---|---|
| 天 | ✓ | 整數，下拉選單 | `5` | 排在哪一天 |
| 時間 | | `HH:MM`（24 小時制） | `15:30` | 卡片左側時間，也用來排序 |
| 停留 | | 文字 | `2 hr`、`45 min` | 時間下方的停留時間 |
| 名稱 | ✓ | 文字 | `表參道 · 竹下通` | 卡片標題，也是地圖標記的名稱 |
| 類型 | ✓ | 下拉選單（見下表） | `購物` | 決定卡片標籤的顏色和英文小標 |
| 英文小標 | | 文字 | `Lunch` | 選填，覆蓋類型預設的英文小標 |
| 重點 | | 核取方塊 | ☑ | 勾選代表主要行程，用粗框顯示 |
| 說明 | | 文字，支援粗體 | `竹下通**下午最擠**…` | 卡片內文 |
| 地圖搜尋 | | 英文或日文名稱 | `Takeshita Street` | Google 地圖按鈕 |
| 緯度 | | 數字，小數 4 位 | `35.6712` | 標在地圖上 |
| 經度 | | 數字，小數 4 位 | `139.7050` | 標在地圖上 |
| 狀態 | ✓ | 下拉選單：已訂／已定／草稿／待確認 | `草稿` | 卡片狀態標籤 |
| 提議者 | | 下拉選單：我／老婆 | `老婆` | 知道是誰加的 |
| 新增日期 | | `YYYY/MM/DD` | `2026/11/15` | 標示 NEW（規則同口袋名單） |

### 排序與地圖規則

- 同一天依「時間」排序。沒填時間的卡片排在當天最後，時間欄顯示「未定」。
- 有填經緯度的卡片才會標在地圖上，標記編號依排序後的順序。交通、移動這類卡片不用填經緯度。
- 當天第一個和最後一個有座標的標記，網頁會自動標成起點和終點。
- 有填「地圖搜尋」但沒填經緯度的卡片，會顯示「待確認位置」。

### 類型對照

| 類型 | 預設英文小標 | 標籤顏色 | 適用 |
|---|---|---|---|
| 交通 | Transfer | 灰 | 新幹線、包車、機場移動、抵達 |
| 住宿 | Hotel | 灰 | check-in、退房、回飯店整裝 |
| 餐廳 | Food | 紅 | 午餐、晚餐 |
| 景點 | Sight | 綠 | 公園、湖、展望台、街道散步 |
| 玩雪 | Snow | 綠 | 滑雪場、雪樂園 |
| 溫泉 | Onsen | 紫 | 泡湯 |
| 購物 | Shopping | 藍 | Outlet、市集、福袋 |
| 寺社 | Shrine | 朱 | 淺草寺、明治神宮 |
| 休息 | Rest | 灰 | 回飯店休息、補眠 |

- 搬資料時，現在的英文小標（例如 Lunch、Dinner、Train、Countdown、Ropeway）會保留在「英文小標」欄，畫面上不會有任何變化。

## 工作表 3：口袋名單

想去但不一定會排進行程的店家和景點。

| 欄位 | 必填 | 格式 | 範例 | 網頁用途 |
|---|---|---|---|---|
| 名稱 | ✓ | 文字 | `大黑家天婦羅` | 名單標題 |
| 分類 | ✓ | 下拉選單：咖啡／麵包甜點／餐廳／居酒屋／玩具童裝／選物／市場／景點 | `餐廳` | 篩選按鈕、標記顏色 |
| 地區 | | 文字 | `淺草` | 副標 |
| 營業時間 | | 文字 | `11:00-20:00` | 顯示；年末年始要另外查證 |
| 搭配哪天 | | 文字 | `Day 5`、`Day 6 方案 B` | 顯示 |
| 說明 | | 文字，支援粗體 | `明治創業的江戶前炸蝦丼…` | 內文 |
| 地址 | | 文字 | `東京都台東区浅草1-38-10` | 顯示；店家的公開地址可以寫 |
| 地圖搜尋 | | 英文或日文名稱 | `Daikokuya Tempura Asakusa` | Google 地圖按鈕 |
| 緯度、經度 | | 數字 | `35.7117`、`139.7967` | 名單的地圖模式、離我最近 |
| 新增日期 | | `YYYY/MM/DD` | `2026/11/15` | 標示 NEW |
| 提議者 | | 下拉選單：我／老婆 | `我` | 顯示 |

- **NEW 標示規則**：新增日期晚於這支手機上次開網頁的時間，就標 NEW。第一次開啟時，改標最近 7 天內新增的項目。
- 「匯出 CSV（給 Google 我的地圖）」的功能保留，資料來源改成這張工作表。

## 工作表 4：準備清單

| 欄位 | 必填 | 格式 | 範例 | 網頁用途 |
|---|---|---|---|---|
| 分類 | ✓ | 文字 | `玩雪裝備` | 分組標題 |
| 項目 | ✓ | 文字 | `防水手套 x4` | 清單項目 |
| 說明 | | 文字 | `毛線手套碰雪會濕透` | 項目下方小字 |

- 網頁上現在的「新增、刪除、勾選」功能會拿掉，改成一個「在試算表中編輯」的按鈕。
- 之後如果想在網頁上直接勾選，再加 Apps Script（目前不做）。

## 工作表 5：飯店

一段住宿一列。

| 欄位 | 必填 | 格式 | 範例 | 網頁用途 |
|---|---|---|---|---|
| 名稱 | ✓ | 文字 | `（待補）` | 顯示飯店名稱 |
| 區域 | ✓ | 文字 | `淺草` | 名稱還沒決定時，改顯示區域 |
| 入住日 | ✓ | `YYYY/MM/DD` | `2026/12/25` | 判斷哪幾天住這裡 |
| 退房日 | ✓ | `YYYY/MM/DD` | `2026/12/29` | 同上；晚數由網頁自動計算 |
| Check-in | | `HH:MM` | `15:00` | 顯示 |
| Check-out | | `HH:MM` | `11:00` | 顯示 |
| 早餐 | | 文字 | `含早`、`不含` | 顯示 |
| 設施 | | 文字 | `大浴場、洗衣機` | 顯示 |
| 地圖搜尋 | | 英文或日文名稱 | | Google 地圖按鈕 |
| 緯度、經度 | | 數字 | | 在每日地圖上標出飯店位置 |
| 狀態 | ✓ | 下拉選單：已訂／已定／草稿／待確認 | `已訂` | 狀態標籤 |
| 備註 | | 文字 | `12/27 房間保留` | 顯示 |

- **對應到每一天**：日期落在「入住日 ≤ 當天 < 退房日」的那一段住宿，就是當晚住的飯店。輕井澤那晚和淺草的日期重疊（淺草的房間保留），這種情況以**入住日比較晚**的那一段為準。
- **不設訂位代號、電話欄位**，原因見「隱私」。飯店本身的公開地址可以用「地圖搜尋」和經緯度表示。

## 工作表 6：選項

下拉選單的來源。每一欄是一組選項，用來設定「資料驗證」。

| 天 | 類型 | 狀態 | 分類 | 人 |
|---|---|---|---|---|
| 1–8 | 交通、住宿、餐廳、景點、玩雪、溫泉、購物、寺社、休息 | 已訂、已定、草稿、待確認 | 咖啡、麵包甜點、餐廳、居酒屋、玩具童裝、選物、市場、景點 | 我、老婆、一起 |

- 這張工作表只能新增選項，**不要改名或刪除已有的選項**，網頁的顏色對照是照名稱判斷的。新增的類型或分類會用預設的灰色顯示。

## 留在網頁程式碼裡的內容

這些內容排版複雜，而且幾乎不會再改，不搬進試算表：

- 封面
- 行前提醒（12 則）
- 購物指南（8 張卡片）
- 交通（11 張卡片）
- 預算

## 隱私

試算表發布到網路後，**知道網址的人都看得到**，規則和網站一樣：

- 可以寫：航班號碼、飯店名稱、大概區域、店家的公開地址。
- **不可以寫**：訂位代號、確認碼、護照資料、電話、email、我們住宿的詳細門牌地址。
