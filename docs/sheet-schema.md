# 行程資料表規格（Google 試算表 → 網頁）

> 狀態：**已上線**。`tokyo-2026/index.html` 的每日行程、口袋名單、行前準備都從試算表讀取。購物清單和花費還沒有網頁畫面。

## 目標

- **以「天」為主**：每天要做什麼，都寫在「行程」表，一列就是一個安排。
- **地點另外建一個庫**：景點、美食、店家各一張表，只記地點本身（營業時間、地址、地圖、門票），不屬於任何一天。同一個地點可以被好幾天引用；還沒被引用的，就是口袋名單。
- **網頁負責顯示**：網頁讀這些表，組出每天的時間軸和地圖，並列出口袋名單、購物清單和準備清單。

## 主從關係

```
旅程
├─ 每日（Day 1–8）……………………… 主
│   └─ 行程（天、時間、去哪裡、當天備註）… 從：屬於某一天
│        └─ 地點 ──引用──▶ 地點庫
│
├─ 地點庫（不屬於任何一天）………… 另一個主
│   ├─ 🏯 景點
│   ├─ 🍜 美食
│   └─ 🛍️ 店家
│   （沒被任何「行程」引用的 = 口袋名單）
│
├─ ✈️ 航班：依「日期」自動掛到那一天
├─ 🏨 住宿：依「入住日／退房日」自動掛到那幾天
│
└─ 整趟共用：🎁 購物清單、💴 花費、🎒 行前準備
```

工作表順序：說明 · 每日 · 行程 · 景點 · 美食 · 店家 · 航班 · 住宿 · 購物清單 · 花費 · 行前準備 · 選項

## 架構

```
Google 試算表 ──（檔案 → 共用 → 發布到網路，整份文件，CSV）──▶ tokyo-2026/index.html
```

- 讀取網址格式：`https://docs.google.com/spreadsheets/d/e/<發布ID>/pub?gid=<工作表ID>&single=true&output=csv`
- 網頁只能**讀**試算表，所有新增、修改都在試算表裡做。
- **離線備援**：每次讀取成功，網頁都會在這支手機上存一份資料。讀不到試算表時改用這份存檔，並在頁面上方顯示「目前顯示的是 MM/DD HH:MM 的資料」。
- **Google 發布的內容有快取**：改完之後，可能要等 1–5 分鐘網頁才會更新。

## 每天的時間軸怎麼組出來

第 N 天的時間軸由下面三種來源組成，依時間排序：

1. **行程表**：「天」等於 N 的每一列。
2. **航班**：「日期」等於第 N 天的航班。出發機場在日本的，以起飛時間排入，否則以抵達時間排入。
3. **住宿**：入住日是第 N 天的，在 Check-in 時間顯示「入住」；退房日是第 N 天的，在 Check-out 時間顯示「退房」。

一張卡片的內容這樣決定：

| 卡片上的 | 來源 |
|---|---|
| 標題 | 行程的「標題」，空白時用「地點」的名稱 |
| 內文 | 行程的「說明」（這天的安排），下面附上地點的營業時間、門票、年末營業 |
| 地圖位置、Google 地圖按鈕 | 地點的經緯度和「地圖搜尋」。沒有引用地點的列（例如交通、休息、還沒決定的午餐）不會標在地圖上 |
| 顏色 | 行程的「種類」 |

- 第 N 天的日期由「每日」表決定。沒有「每日」表時，以 Day 1 = 2026/12/25 往後推算。
- **每晚住哪裡**：日期落在「入住日 ≤ 當天 < 退房日」的那一段住宿。日期重疊時，以入住日比較晚的那一段為準，例如 12/27 住輕井澤，淺草的房間保留。
- **口袋名單**：地點庫裡沒有被任何一列行程引用的地點。

## 通用規則

- **第 1 列是表頭**，網頁是用**欄位名稱**找資料，所以欄位可以調換位置。表頭列有設保護（警告模式）。
- **可以自己加欄位**：網頁不認得的欄位會被忽略。試算表是公開的，見「隱私」。
- **整列空白會被忽略**。格式有問題的列會被跳過，並列在網頁最下方的「資料問題」區塊，寫出是哪張表的第幾列、什麼問題。例如行程引用了一個地點庫裡不存在的名稱。
- **說明類欄位**支援 `**粗體**` 和儲存格內換行，不支援其他 HTML。
- **時間**：`HH:MM`（24 小時制），時間欄已設成純文字。**日期**：`YYYY/MM/DD`。
- **經緯度**：必須查證，不可以用猜的。要落在日本範圍內（緯度 24–46、經度 122–154）。空白時，地圖上不標，卡片顯示「待確認位置」。
- **Google 地圖按鈕**：使用「地圖搜尋」產生 `https://www.google.com/maps/search/?api=1&query=<地圖搜尋>`。這欄空白時，改用「名稱」。
- **狀態**：已訂／已定／草稿／待確認。新增的內容預設是「草稿」。
- **提議者／新增日期**：新增日期晚於這支手機上次開網頁的時間，就標 NEW；第一次開啟時，改標 7 天內新增的項目。
- **地點的名稱就是它的識別**：行程是用名稱引用地點的，改地點名稱時，行程表裡引用它的列也要一起改，否則會出現在「資料問題」。

**加一個新的安排**
- 地點已經在地點庫裡：到行程表新增一列，填天、時間，「地點」從下拉選單選。
- 地點還不在庫裡：先到景點、美食或店家表加一列，再回行程表選它。
- 只是先佔一個時段，例如「Day 5 晚餐，還沒決定吃哪家」：地點留空，標題寫「晚餐 · 原宿」，說明寫候選店家。

## ✈️ 航班

日期、航班號、航空公司、出發機場、起飛時間、抵達機場、抵達時間、航廈、狀態、備註。時間都是當地時間。

## 🏨 住宿

名稱、區域、入住日、退房日、Check-in、Check-out、早餐、設施、地圖搜尋、緯度、經度、狀態、備註、參考連結。
- Check-in／Check-out 填我們預計入住和退房的時間，這也是時間軸上的時間。
- 名稱還沒決定時，卡片改顯示區域。

## 🎁 購物清單

品項、給誰、在哪買、數量、預算、負責人、買了沒（核取方塊）、備註。「在哪買」和店家表的名稱相同時，網頁會連過去。

## 💴 花費

日期、項目、分類（交通／住宿／餐飲／門票／購物／其他）、金額（日圓，只填數字）、付款人、付款方式（現金／信用卡／Suica／其他）、備註。網頁會依分類和日期加總。

## 🎒 行前準備

分類、項目、說明、負責人、完成（核取方塊）。勾選在 Sheets app 裡做，網頁只負責顯示。

## 說明（第一張工作表）

給直接編輯試算表的人和 AI 助手看的規則精簡版，內容對應 `AGENTS.md`。網頁不讀這張表。

## 選項

所有下拉選單的來源：天、狀態、人、預約、美食類型、店家類型、景點類型、交通方式、花費分類、付款方式、地點（自動）、種類。

- 「地點（自動）」是公式，會自動列出景點、美食、店家三張表的所有名稱，**不要手動改**。
- 其他欄位**只能新增選項，不要改名或刪除已有的選項**，網頁的顏色對照是照名稱判斷的。

## 留在網頁程式碼裡的內容

封面、行前提醒（含小兒急診等緊急資訊）、購物指南、交通說明卡片、預算。

## 隱私

試算表發布到網路後，**知道網址的人都看得到**：

- 可以寫：航班號碼、飯店名稱、大概區域、店家的公開地址。
- **不可以寫**：訂位代號、確認碼、護照資料、保單號碼、電話、email、我們住宿的詳細門牌地址。
